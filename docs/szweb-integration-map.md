# szweb · Final design-to-CMS integration map

This records the implementation in `src/features/theme/themes/szweb` and its route adapters. The new theme keeps the concept's white–black–white rhythm and text-led indexes while taking article, search, pageview, account, and friend-link data from the existing application services. Projects and the small `Now` section remain theme-local configuration; no new CMS model was added.

## Capability map

| Concept / old capability | Existing source | Final szweb entry and actual behavior | Implementation status and limits |

Up to eight public tags link to filtered posts. | Implemented on live query results. | Article preview and return to list | `src/features/posts/queries/index.ts`; `postBySlugQuery` | `ArticlePreview` loads the selected post by slug, extracts its first three real paragraph nodes from `contentJson`, and clips each displayed paragraph to 400 characters. | Full-text search | `src/routes/_public/search.tsx`; `src/features/search/queries` | `/search`; debounces the URL `q` by 300 ms and uses the existing Orama/KV search results. | Projects | No prior CMS model | `/projects` and `/projects/$projectId`; typed entries in `themes/szweb/site.ts` drive the list and detail pages. | Implemented as theme-local illustrative content. Project entries are not CMS-backed; external visit links appear only when a URL is configured. |

| Admin and OAuth consent | Existing `admin/*` and `/oauth/consent` routes | Admin routes and OAuth consent remain application routes; szweb links to the admin area for admins and supplies the shared public/user shells. | Existing authorization/business paths are retained; this theme pass does not claim live external OAuth provider verification. |
| RSS, Atom, sitemap and SEO | Existing feed/SEO routes and route metadata | Footer exposes RSS, Atom and navigation. ## Validation snapshot

The owner reports 137 unit tests across 11 files, three local guard checks, TypeScript, build, and lint passing (zero lint errors and three existing warnings). The stable strict browser run covered 40 views and 18 checks, all passing with zero errors and zero external requests. The prior table-hydration and UTF-8 KV-key issues are fixed (`tbody` insertion and byte-budgeted view-count batching). Sixteen interaction checks passed, including English, dark mode, and the mobile menu; the separate 12-check account report passed real profile, friend-link, logout, and admin-settings-save flows. Supplemental checks covered search 503/retry, dark images, 404, and invalid-auth states. `product/report.json` passed 6/6 checks with zero errors and zero external requests for reading/TOC, code copy, and blank auth-form states. Six feed endpoints returned HTTP 200, four added routes appeared in the sitemap, reduced-motion checking observed no animation, and project keyboard/focus checks passed. The authenticated post-edit SSR mismatch was fixed with `ClientOnly`; final TypeScript and build checks passed.

The corrected comment browser run has now passed 24 checks with zero errors and zero external requests. A separate `adminSettingsCheck` reports a Breadcrumbs hydration warning in an unmodified component; its baseline has not been established, so that report is kept separate from the passing strict browser run. The local UI uses mocked or disabled email/OAuth integrations, so local results do not validate live delivery or a remote provider login.

## Boundaries

No D1 schema, migration, service contract, MCP capability, production binding, or deployment behavior was added for this theme. Existing routes and services continue to own data and authorization. The theme-local project configuration and editorial media map are presentation data only.
